# Архитектура NexusRPG1 — фактическое состояние

**Обновлено:** 22.10.2026. Этот документ описывает проверенную по исходникам архитектуру, а не запланированные несуществующие модули.

## Маршрут исполнения

```text
launcher.py ──> python -m src.server.app
                          │
                          ├── Flask app: templates/, static/
                          ├── src.config
                          ├── src.core.engine.GameEngine
                          │     ├── src.ai.AIConnector / KnowledgeBase
                          │     ├── src.content.* (включая legacy V2-V5)
                          │     ├── src.systems.* (системы игры)
                          │     └── src.world.* (карта / события / NPC)
                          ├── game_data/active/** (JSON)
                          └── saves/ (локальные сохранения)
```

У приложения есть **одна** каноническая реализация `GameEngine` в `src/core/engine.py`. Корневые дубли `game_engine.py`, `ai_connector.py`, `config.py` удалены из текущего дерева и доступны в истории Git.

### Загрузка JSON

`src/ai/knowledge_base.py` рекурсивно читает `game_data/active/**` и группирует документы по базовому имени. При совпадениях версий использует `PREFERRED_FILES` или приоритет версии/размера. Ключи API по-прежнему **базовые имена файлов**, независимо от категорий. Дубли базового имени в разных активных папках — ошибка. `game_data/archive/` не участвует в этой загрузке.

Для устаревших функций персонажа `src/content/v4_legacy.py` ищет требуемый JSON в том же активном каталоге. Это временное решение совместимости; в перспективе лучше зависеть от общей KnowledgeBase, но переход требует тестов эквивалентности.

### Компоненты

| Каталог | Реальные файлы / функции |
|---|---|
| `src/ai/` | `connector.py`, `knowledge_base.py` |
| `src/core/` | `engine.py`: GameEngine, GameState, DiceRoller |
| `src/content/` | `creation_data.py`, `base.py`, `v2_legacy.py` ... `v5_legacy.py` |
| `src/server/` | `app.py`: Flask API и маршруты |
| `src/systems/` | `combat.py`, `companions.py`, `game_systems.py`, `mechanics.py`, `quests.py`, `subsystems.py` |
| `src/world/` | `galaxy.py`, `simulation.py`, `procedural.py`, `npc_registry.py` |

`src/utils/__init__.py` — пока только пакет, не самостоятельная подсистема.

### Ограничения

- `GameEngine` крупный монолит. Разделение на сервисы — самостоятельный рефакторинг с тестами без изменения игрового поведения.
- `src.server.app.engine` — единый объект на процесс, а не отдельная независимая сессия для каждого игрока.
- Текущий набор тестов в основном модульный и smoke, не покрывает настоящие многопользовательские сценарии и AI-инференцию.
- Разные модули могут описывать схожие домены (QuestTracker / QuestChains / ProceduralQuestGenerator; WorldSimulator / WorldTicker), но прямое удаление без анализа контрактов недопустимо.

### Принципы дальнейшего рефакторинга

1. Не создавать второй экземпляр одной механики в другом каталоге.
2. Один источник истины для игрового состояния и проверяемых эффектов; AI GM формирует нарратив на основе состояния.
3. Отдельно хранить **код**, **активные данные**, **архивную справку**, **документацию ЛОРа** и **сохранения пользователя**.
4. Не разрабатывать новые механики, магию, квестовые хуки до следующей согласованной фазы после ЛОРа.
5. Каждый перенос кода — тесты сохранения поведения и сравнение загрузки/сериализации.
